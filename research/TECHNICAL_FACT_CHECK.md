## 1. GetCourse API

| Утверждение в книге | Результат проверки | Источник |
|---|---|---|
| Export API предназначен для периодической выгрузки, а не постоянного получения новых объектов | Подтверждено текущей документацией | https://getcourse.ru/help/api |
| Лимит Export API — 100 запросов за два часа на аккаунт; учитываются запросы проверки готовности | Подтверждено | https://getcourse.ru/help/api |
| Экспорт выполняется в один поток: новый экспорт не формируется, пока не завершён предыдущий | Подтверждено | https://getcourse.ru/help/api |
| Для оперативной передачи изменений можно использовать callback / операцию «Вызвать URL» в процессах | Подтверждено, но callback не предназначен для массовой передачи данных | https://getcourse.ru/blog/276215 |
| Callback-вызовы выполняются последовательно; следующий вызов ждёт ответа предыдущего | Подтверждено | https://getcourse.ru/blog/276215 |
| В процессе можно настроить ветку ошибки для сбоя принимающего сервиса | Подтверждено | https://getcourse.ru/blog/276215 |

Редакторское следствие: в архитектурных примерах нужно различать периодическую выгрузку, событийный callback и массовый экспорт. Приём callback должен быть быстрым; длительную обработку следует выполнять после надёжного сохранения события.

## 2. OpenAI API: обучение и хранение данных

| Утверждение | Результат проверки | Источник |
|---|---|---|
| Данные API по умолчанию не используются для обучения и улучшения моделей, если клиент явно не согласился на передачу данных | Подтверждено | https://developers.openai.com/api/docs/guides/your-data |
| Abuse monitoring logs по умолчанию могут храниться до 30 дней; предусмотрены исключения и специальные режимы | Подтверждено | https://developers.openai.com/api/docs/guides/your-data |
| Хранение application state зависит от endpoint и используемых функций | Подтверждено | https://developers.openai.com/api/docs/guides/your-data |
| Для Responses API действует отдельное правило: данные ответа по умолчанию или при store=true могут храниться не менее 30 дней | Подтверждено текущей документацией | https://developers.openai.com/api/docs/guides/your-data |
| Zero Data Retention и Modified Abuse Monitoring доступны не автоматически всем аккаунтам; требуется одобрение и соблюдение ограничений | Подтверждено | https://developers.openai.com/api/docs/guides/your-data |

Редакторское следствие: нельзя писать, что API-данные «не хранятся» только на основании того, что они не используются для обучения. Нужно отдельно проверять endpoint, application state, abuse monitoring, параметры store и доступные организации режимы хранения.

## 3. OpenAI Structured Outputs

| Утверждение | Результат проверки | Источник |
|---|---|---|
| Structured Outputs обеспечивает соответствие результата заданной поддерживаемой JSON Schema | Подтверждено | https://developers.openai.com/api/docs/guides/structured-outputs |
| Поддерживается не весь стандарт JSON Schema: есть ограничения по типам, структуре и ключевым словам | Подтверждено | https://developers.openai.com/api/docs/guides/structured-outputs |
| Соответствие схеме не гарантирует смысловую правильность результата; модель может допускать ошибки, а отказ или неполный ответ требуют отдельной обработки | Подтверждено | https://developers.openai.com/api/docs/guides/structured-outputs |

Редакторское следствие: формулировать Structured Outputs как гарантию структуры, а не истинности, полноты или правильности фактов.

В главе 3 n8n описан на уровне назначения, вариантов размещения и эксплуатационных обязанностей. При подготовке конкретных инструкций по очередям, retries, секретам, обновлениям и резервному копированию нужно сверяться с текущей документацией и редакцией продукта.

Не переносить свойства облачной версии на self-hosted без проверки и наоборот.
